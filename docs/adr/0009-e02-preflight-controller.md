# ADR 0009 — E02 controller preflight, with live execution closed

Status: implementation and executable preflight tests. This supersedes ADR 0008 only for the items
below. No business feature, live model task, scheduler, automatic merge, provider mutation or deploy.
PR #1 was squash-merged at 4e51cc18c49c7872a175cb07c4b3de760360be39 after exact head/base/snapshot/CI

## Trust boundary and fixed release

`npm run controller:export -- <repo> <NEW outside directory> <policy file>` bundles the controller
and AJV/schema dependencies using the already lock-pinned esbuild 0.28.2 supplied with tsx. The
release includes the supervisor, probe, policy, task/review/receipt JSON Schemas and a manifest.
No runtime import resolves into candidate node_modules. The manifest records source Git SHA/tree,
version and exact hashes of every executable/policy/schema byte. A caller must obtain the manifest
hash independently from the owner-approved release, never from the candidate's proposed manifest.
Export is a trusted maintainer operation, not task permission and not production activation.

Controller entry, policy, signer public keys, schemas, registry and state stay outside worker write
access. Policy is loaded from that verified release, not accepted as a worker-provided argument.
Review receipts are signed by the trusted reviewer/publisher boundary and bind task/run/base/head,
spec, independently observed snapshot hash and review content. Signatures alone do not establish
model provenance: only a trusted publisher may issue one after validating the actual CLI result.
Keys generated by fixtures are disposable test identities, never live approvers.

`sandboxPlan` builds a complete named permission profile as a CLI override and includes managed
requirements. The installed Mac CLI is 0.153.4: its syntax is `codex sandbox ... -- executable args`
(no `macos` subcommand in this app-bundled version). The profile denies filesystem reads by default,
allows minimal runtime paths, the Node binary directory and OS OpenSSL configuration, permits the
candidate and run scratch writes, keeps the fixed release readable only, denies common Git/state,
.git/.codex/.claude/.env access and disables network. No environment inheritance or token is used.
The profile and runtime binary hashes are recorded. Failed/unsupported sandbox setup has no fallback.

The actual Mac test launches this installed Codex sandbox, not a mock chmod check. It verifies
EPERM for policy write/rename, state tampering, a symlink write into policy, a synthetic out-of-scope
read and signaling its ancestor. A permitted worktree write must succeed. It also launches a real
child/grandchild under the same sandbox and checks timeout cleanup. No real Keychain/secret is read.

Limits: this proves the credential-free **command worker** profile, not a live model harness with
ChatGPT/Claude OAuth. Safe authorization of that credentialed parent, provider-only network access,
all auto-loaded project configuration and protected CI/receipt publication require separate live
provisioning and owner approval. The ordinary host account can still modify its own release; the
boundary is the sandboxed worker, not a same-UID chmod claim. No global configuration/OS account was
changed. Branch protection remains unavailable under the current private-repository plan; integration
continues to require the owner's explicit approval.

## One repository lease and a durable run

`repositoryState` canonicalizes Git's absolute common directory; all linked worktrees share one
`zao-e02-controller/repository.lock`. Atomic mkdir chooses one process. The owner records repository
identity, task/run IDs, PID/start time, host, canonical worktree, token and advisory expiry. An existing
lock is never stolen, even with an expired timestamp or dead PID. A missing/partial owner record also
blocks. No automatic stale-lock deletion or PID-only recovery command is provided.

The single writer stores a fsynced temp JSON then atomic rename and directory fsync. A task journal
binds signed approval digest, release hash, original run ID, branch, original start time and counters.
INTENT is durable before branch/model/push/PR effects; DONE is persisted afterward. On restart an
INTENT requires read-only reconciliation. A proven existing result is adopted; unknown results block
without replay. Completed branch/PR/model operations are reused. Read-only current Git/CI/PR identity
observations are refreshed. A different run/spec/release cannot silently reuse an old task journal.
The tests race two real processes in two real Git worktrees and require exactly one winner.

Recovery after a killed lease owner is deliberately an owner operation: check PID plus start/host,
ensure the run guardian/processes are gone, inspect every INTENT against remote branch/PR and model
records, preserve evidence, and only then authorize maintenance of this exact lock/run. Elapsed lease
time is insufficient. The preflight exposes no unapproved unlock switch.

## Adapters, observations and stopping

The command registry uses an operation enum, absolute tools/cwd, strict ref/SHA validation and argv
arrays; no free shell string, shell expansion, inherited Git/provider credential or injected loader
variable is accepted. Implementation, verification, publication and static review are distinct
operations. The registry's external-service commands are inert preparation. `DisabledLiveAdapter`
always rejects, and the controller rejects every adapter with mode LIVE. `runner:dry-run` uses only
in-memory fake services in a temporary repository, a real common lock and real durable journal.
It creates no real branch/PR/model request. The old proposal CLI remains historical and unconnected.

The controller validates signed approval/expiry, independent observed head/diff/check exits and
allowed/protected paths before push/draft. Draft identity, current base/head/PR and signed review
receipt are checked before AWAITING_APPROVAL. Missing/pending/stale CI and unknown verdicts stop.
A failed CI or CHANGES_REQUIRED can consume at most two repair rounds (three implementation and
three review calls maximum). Auth/quota/credits/unknown side effects block without provider fallback.
There is no merge operation. No task may self-sign or overwrite the controller's state/result.

`runBounded` starts a trusted guardian in a new POSIX session/process group. Workers have only their
explicit env and ordinary stdio, never the guardian's IPC descriptor. Timeout/cancel/worker exit or
controller IPC disconnect terminates that owned group; TERM is followed by KILL. The guardian remains
alive anchoring the group ID until final KILL, avoiding group-ID reuse. Output is bounded. Tests check
child/grandchild cleanup on timeout, cancel, worker abnormal exit and controller SIGKILL, while an
unrelated fixture process survives. The Mac test additionally exercises the real sandboxed command.

Containment limit: a deliberately detached `setsid` descendant can escape a POSIX process group;
guardian SIGKILL or host failure also cannot be handled by that guardian. These are **not** claimed
contained. No arbitrary model-generated process tree is enabled here. Before live use, provision and
verify stronger job/VM containment or an enforceable no-detach worker interface. This preflight does
not install launchd/cgroups/a VM or grant OS privileges. Live authentication, GitHub App/token scope,
CI workflow/App identity checks, merge-tree receipts, publish reconciliation and usage enforcement
must be wired in that reviewed environment. Fake results are never labeled external acceptance.
