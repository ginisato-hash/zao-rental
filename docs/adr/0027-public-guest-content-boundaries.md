# Public P0 guest / content boundaries

The owner approved PUBLIC_P0_APPROVAL and the exact dedicated development guest FK/role
proposal. The later guest approval resolves the earlier automatic review rejection; it
is not a new production or general database authority.

Guest capability is256 random bits in an HttpOnly/SameSite=Lax/Path=/ cookie, Secure on
HTTPS. Only its SHA256 is stored. This is not a staff role/session. Server-owned actor
registry preserves14 ownership/audit FKs without making a guest an employee. Every
existing domain authorization rechecks the context. Staff-only custody/transfer/admin
permissions and real staff session requirements remain. Revocation serializes with stock
writes; draft writes lock their context and check the revision. Development context TTL
is86400s; production recovery, abuse/rate limits and retention are launch blockers.

Dates/people/selections are saved before stock acquisition. Recommendation + whole-group
advisory use existing sizing/price services. Editing before checkout creates a new preview
revision. First checkout freezes the saved contact and request keys, then obtains the
whole HOLD and immutable quote. Estimate book/calculation changes require explicit new
server snapshot acceptance; no browser amount is authoritative. Response replay uses the
same persisted keys. Payment adapter exists only in tests/flow-app. Normal production
composition is disabled and cannot enable this test adapter from a browser flag.

Premium candidates are restricted to verified model/season/variant IDs from the current
content release, and rechecked immediately before HOLD. Public model source and sizes
come from actual synthetic ledger rows, never the full manufacturer catalog. Content
release checks bilingual revisions, shop verification, photo rights and immutable bytes.
No Product/Offer or LocalBusiness claims are emitted without approved commercial/NAP data.

Existing content workflow now has a dedicated PG repository and explicit CONTENT_EDIT,
CONTENT_BULK, CONTENT_PUBLISH grants (none by role default). It serializes revisions,
audit, outbox, bulk/release manifests and photo jobs. Private immutable media bytes use a
bounded development PG adapter, not a new external provider. Only approved derivative
paths are public-readable; original upload digest paths are refused. Rights withdrawal
removes model/media/sitemap; withdrawn pages redirect to an explicit410 response.
Prices and physical stock have no CMS write grants. Real media and material/rights
curation remain pending; the tested corpus is synthetic.

The locale catch-all causes Next's link lint heuristic to flag pre-existing staff links.
Private staff/preview navigation intentionally performs a document reload to discard
session-scoped caches; the exception is scoped to those files. Public content uses Link.

Production indexing stays off. Positive indexability is verified only in the isolated
loopback test app, with unique initial SSR metadata/content, reciprocal ja/en/x-default,
private/query noindex and sitemap exclusions. Performance evidence is local development
navigation/layout, not field CWV, search ranking or a real phone test.

Page locale/SEO proxy excludes API routes: it does not read or clone upload bodies.
Both normal and test Next configs set API noindex/private-no-store independently.
The existing 9MiB base64 transport regression exposed the initial blanket proxy's10MiB
clone truncation (HTTP500 instead of manifest-level409); it is preserved and rerun.
Endpoint JSON/group/photo limits and CSRF/auth remain unchanged. This follows installed
Next16.3.4 body-streams code and [official proxy body-limit documentation](https://nextjs.org/docs/app/api-reference/config/next-config-js/proxyClientMaxBodySize).

Initial pageshow now verifies the staff session without remounting a typed form; persisted
BFCache restoration still hides all staff content before revalidation. Anonymous401 API
precompilation in the synthetic launcher isolates a separately traced Next dev HMR SYNC
hash/reconnect reload before browser interaction. No runtime HMR code, authentication,
body cap or test timeout was disabled. See PUBLIC_P0_VERIFICATION for both counterexamples.
