# ADR0028 — Production Readiness P1 without activation

P1 starts from PR11 merge0a639cb46e58721f0b52a5095674aae4e76c325b. Exact prior CI/review/tree and final progress were verified; the old worktree remains untouched. No business price/time/inventory rule changes. Keep existing modular monolith, libraries and SQL migration system.

## Guest security

GuestSecurity is a server-composed boundary, not a staff role. Validated explicit policy specifies access/absolute/recovery/replay/retention durations and peer/global fixed-window budgets. No production numeric defaults were selected. An immutable DB policy fingerprint rejects divergent parameters under the same version across processes. Only synthetic tests supply numeric settings. Normal production composition remains unconnected, and guestHandler refuses a production request without a security adapter. Real trusted-ingress implementation and approved policy remain deployment gates; never derive trusted peer identity directly from arbitrary X-Forwarded-For.

Rate counters use atomic PostgreSQL writes in stable global-then-peer order. Global admission bounds anonymous peer-row growth, and expiry cleanup is bounded. Peer labels are HMAC pseudonyms, not raw addresses. These are application admission budgets, not proof of edge DDoS protection or capacity at production traffic. No paid CAPTCHA/edge/WAF was introduced.

Recovery is possession of a256-bit CSPRNG recovery code, not email/booking-ID knowledge. Only its digest is stored. Enrollment requires active current capability and settings revision. Redemption serializes with stock writes and context updates, rejects revocation/absolute expiry, consumes the code and rotates the old access token. Standard HMAC-SHA256 with the existing server secret and purpose/context/request/code-digest separation gives a deterministic opaque replacement for a bounded identical-request replay. The DB stores only the new token hash, not plaintext or encrypted session tokens. Browser sessionStorage holds only a random request ID; secrets are neither stored there nor placed in URLs. A lost response can be replayed with the same recovery code and request ID, yielding the same token and expiry. Other keys, later replay expiry, re-enrollment or logout cannot resurrect it. This is guest capability recovery, not a new staff password/session protocol. Key continuity/rotation must be operationally approved before live deployment.

Every domain service still verifies current context hash/expiry and existing owner/store/stock guards. The P0 disputed lock-wait scenarios are now committed regression tests. Recovery does not replace the actor, mutate stored request keys, release stock, extend HOLD600s, rewrite prices or confirm payment.

Retention is deliberately scoped: remove expired recovery/replay material and redact expired unsubmitted draft input, with durable cursor state and bounded SKIP LOCKED batches. No DELETE of actor/booking/contract/audit and no automatic stock release. Submitted preview/profile/contact/contract retention and customer deletion workflow require legal retention decisions and remain blocked. A policy change cannot silently apply another version's retention period. The sweeper is a service method/test, not a scheduler or autonomous job.

[OWASP recovery guidance](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) informed high-entropy, expiring, single-use capabilities and abuse controls. [OWASP session guidance](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) informed server-side expiry/rotation and cookie controls. These sources do not approve our operational TTLs or deployment.

## Square boundary

The new adapter emits only the Sandbox origin, fixed API version2026-08-19 and exact create/get shapes. It has no default network transport, credential/environment reader or normal booking activation. Source acquisition and transport calls have bounded deadlines and masked errors; ignored cancellation still settles the service call without retry. A future credentialed transport must bind the merchant/Sandbox and honor AbortSignal to terminate its underlying network resources. Existing BookingService still rejects SQUARE_UNCONNECTED: chargeReady=false and simulated payment is test-only. No actual Square/Sandbox requests were made.

Official [CreatePayment](https://developer.squareup.com/reference/square/payments-api/create-payment) and [GetPayment](https://developer.squareup.com/reference/square/payments-api/get-payment) define stable idempotency/source/amount and lookup by payment ID. UNKNOWN without an independently verified provider ID is a reconciliation gate; do not invent a lookup-by-idempotency endpoint, list unrelated payments or issue a replacement POST. Tokenized card payments only are planned; CASH/EXTERNAL are refused. Webhook [signature validation](https://developer.squareup.com/docs/webhooks/step3validate) uses configured URL plus raw bytes. Signed callbacks trigger fresh lookup and exact money/currency/reference/location/merchant matching rather than trusting callback status. Existing durable event dedup/order/UNKNOWN protections remain. External webhook/credentials, real Sandbox E2E and enabling the service adapter are separate future operations.

## Content/import/device/launch

Keep PostgreSQL content revision/audit/outbox and current rights-aware rollback. PrivateImmutableObjectStore is provider-neutral; provider/credentials are absent. Public derivatives are verified against current CMS authorization both before and after object fetch, with digest integrity, and never via an original digest or broad public bucket. Cached CDN invalidation and provider rollback await provider choice.

Stock import produces a deterministic source-hashed plan with exact registered model/season/SKU/variant, explicit store/unit/quantity and immutable Asset IDs. Manufacturer catalog is not shop receipt. Unknown ADD/REPLACE, mixed units, duplicate locators/IDs and changed sources remain reconciliation issues. Successful validation does not create stock: authorized ledger import commit and real documents remain separate. No manufacturer SKU coverage, real200wear distribution, or actual300gear details are claimed.

Camera permission failures distinguish denial/missing device, preserve manual fallback and never claim receipt. Offline stops only owned tracks, disables new submissions, and reconnect does not auto-replay/confirm/restart. Persisted loan-cycle return batches stay server authoritative. Width/touch emulation is not actual iOS/Android camera or CWV field evidence. Categorical LAB/FIELD metrics reject arbitrary URLs/PII.

LaunchReadiness requires complete evidence bound to head, policy revision and validity; it performs no deploy and grants no permission. Pending gate file contains no invented commercial values. No production noindex/payment/host protection was removed.
