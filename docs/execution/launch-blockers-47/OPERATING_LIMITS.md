# 作業リスト印刷・CSV出力の運用上限（Issue #47 / PR #73、2026-11-20 後任B）

TD独立レビュー [#7030845802](https://github.com/ginisato-hash/zao-rental/pull/73#issuecomment-7030845802) の「運用制限の明示」に対応する記録。上限は**DB負荷と印刷物の正確さを守るための意図的な有界化**であり、「無制限に全件印刷できる」とは主張しない。

| 経路 | 上限 | 上限を超えたとき | 全件を得る経路 |
|---|---|---|---|
| Dashboard → 作業リスト（Documents） | 期間31日、1店舗・各panel（貸出予定／返却予定）1,000件 | 行を一切出さない（部分リストを作らない）。同じsnapshotの日別件数を表示し、日ごとの完全な作業リストへ誘導 | 日ごとの作業リストを開いて印刷 |
| 上記の「1日分」 | 1店舗・1日・各panel 1,000件 | その日は作業リストを作らず、予約一覧のCSV出力へ案内 | 予約一覧で「受取（または返却）方向・その日」を絞ってCSV出力 |
| 予約 / 顧客 / 在庫 / レポートのCSV | 1回5,000行 | 出力全体を拒否（`EXPORT_TOO_LARGE`、画面に「条件を絞ってください」） | 店舗・期間・状態などを絞って複数回に分けて出力 |

## システム内に完全な印刷・出力経路が無い範囲（正直な記録）

- **1店舗・1日で、受取または返却が5,000件を超える場合**：作業リスト（1,000件）もCSV（5,000件）も全件を1回では出せない。予約一覧の画面（ページ送り）では全件を閲覧できるが、1つの印刷物・1つのファイルにはならない。
- 現在の店舗規模（蔵王の2店舗）では1日あたりの予約数はこの上限より桁違いに小さいと見込む。ただし、実績値で裏付けた数字ではない。
- この範囲が必要になった場合は、安定した並び順（`日付, 時間帯, 作成時刻, id`）によるkeyset分割を、1つのsnapshot内で有界に追加する。無限SQLや架空の件数は使わない。

## 関連する保証

- 作業リストの件数・日別件数・行は、READ ONLYの同じsnapshotから取得し、返す直前に職員のsession・権限・店舗scopeを再確認する。
- 上限を超えたページを⌘P / Ctrl+Pで印刷しても、「不完全なため作業リストとして印刷できません」という文だけが出る。
- CSVは各画面と同じ読取・絞込みをページ分割なしで実行したもの。保存されるのは、要求した画面・session・表示言語が変わっていない場合だけ。
