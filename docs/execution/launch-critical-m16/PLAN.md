Implementation details resolved during M1.5 CI/review waiting:
- Preserve the legacy immutable capture table. It is the durable canonical confirmed-event source; enqueue after commit (and reconcile missing rows from that source) so a queue/provider failure cannot roll back confirmed business state. Outbox unique business key uses confirmation generation1, not mutable booking.version.
- Do not persist messages/codes or enqueue invalid placeholder events. Recovery outbox links existing recoveries by booking/request; derive its code in memory from the existing purpose/key/version and verify its stored hash. Add only an explicit email-request method/purpose to BookingRecovery using the same table/exchange/revoke path; no new token store.
- Confirmation sends a non-bearer /{locale}/reservation link and canonical booking reference; QR is available after normal BookingAccess/Recovery, never an authorization bypass. Other event names exist in the domain but enqueue rejects them until an authoritative producer/template is implemented.
- Reserve SENDING/attempt/fence before calling adapter; ambiguous timeout or stale SENDING is UNKNOWN and lookup-only. No lease-expiry retry. Definite NOT_ACCEPTED gets delayed bounded retry; malformed receipts are UNKNOWN. Provider Message ID is allowlisted and never a raw response.

New manual generation can follow an eligible SENT/exhausted-known-not-accepted record, with stable request ID, required enumerated reason and per-booking cooldown/day limit. Reuse ops_history/ops_requests; do not let free-text reason capture email/token.
- Local public recovery requests need an explicit owned-loopback GuestSecurity guard; production uses the existing verified ingress guard. Same generic response for absent/foreign email or booking, no raw code/token JSON/URL. Existing guest logout remains separate from independently saved read capability, and recovery revoke invalidates its exchanged read capability.
