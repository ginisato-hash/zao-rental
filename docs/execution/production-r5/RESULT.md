## Invariant-by-invariant

- **Closed category/unit enumerations, exact catalog matching, no fuzzy resolution** — [stock-import-plan.ts:12](../../../packages/core/src/content/stock-import-plan.ts) rejects any `unit` outside the 4 fixed values and any `sourceKind`/`intent`/`storeId` outside their own fixed sets; `family`/`category` is checked against the 7-value set at line 21. Model/variant resolution requires an **exact** 4-field match (`id`+`modelId`+`season`+`manufacturerSku`, line 15) — `v.length!==1` (zero or ambiguous matches) is rejected (`EXACT_CATALOG_MAPPING_REQUIRED`), never fuzzy-resolved. `expectedUnit()` (line 7) derives the one legal unit per family and rejects any mismatch (`UNIT_MISMATCH`).
- **Asset UUID permanence** — asset IDs are caller-supplied (matching real physical serials/pre-assigned IDs, not server-generated), but every layer independently guards against reuse: format-validated as a UUID and checked for in-batch duplicates at plan time ([stock-import-plan.ts:18](../../../packages/core/src/content/stock-import-plan.ts)); checked against **existing** `ledger_assets` rows at both dry-run (`import-staging.ts:41`, `ASSET_ALREADY_EXISTS`) and commit time, where the existing-ID set is **re-queried fresh inside the commit transaction** ([inventory-service.ts:82](../../../packages/core/src/operations/inventory-service.ts)), not reused from stage time — closing the TOCTOU gap a stale check would leave open between staging and commit.
- **Dry-run is genuinely zero-mutation** — `stageStockImport`/`commitImportDryRun` ([import-staging.ts](../../../packages/core/src/content/import-staging.ts)) are pure functions with no database access at all; the only persistence in `stageImport()` ([inventory-service.ts:53](../../../packages/core/src/operations/inventory-service.ts)) is one `INSERT INTO ops_import_stages` (staging metadata), never a write to `ledger_assets`/`ledger_poles`/`wear_pools`.
- **Transactional all-or-nothing** — `commitImport`'s entire per-row apply loop runs inside one `OperationsContext.transaction()` ([context.ts:20](../../../packages/core/src/operations/context.ts)): real `BEGIN`/`COMMIT`, and **any** thrown error (constraint violation, `FlowError`, anything) triggers `ROLLBACK` before the error propagates — a failure partway through leaves zero partial writes. The same transaction also holds a global `pg_advisory_xact_lock(71820600)`, serializing imports against every other business-mutating operation in the app (bookings, transfers, custody), so a concurrent commit can't race the fresh existing-ID check above.
- **Rerun idempotency** — enforced **twice**, independently: (1) the generic `OperationsContext.idempotent()` layer ([context.ts:32](../../../packages/core/src/operations/context.ts)) keys on `(actor, request_key)`, stores a fingerprint of the input plus the result in `ops_requests` **inside the same transaction** as the business writes (so a rolled-back attempt is never remembered as done, and a committed one always has a matching cached result — no split-brain), and replays the cached result on a repeat key without re-running `work()`; (2) `commitImport` additionally checks `ops_import_commits` keyed by the caller's own `v.id` ([inventory-service.ts:81](../../../packages/core/src/operations/inventory-service.ts)) — even a client that generates a fresh idempotency key by mistake can't double-apply the same staged import, and a changed `stageSha256` against the same `id` is rejected (`IDEMPOTENCY_MISMATCH`) rather than silently re-applied.
- **Cross-actor hijack of a pending stage** — `commitImport` rejects with `FORBIDDEN` if the committing actor differs from whoever staged the import ([inventory-service.ts:79](../../../packages/core/src/operations/inventory-service.ts)).
- **`acceptRealData` cannot itself assert real-ness** — the declaration's coverage counts are recomputed in SQL from what the commit actually applied (`real_data_accept`), not trusted from caller input; the caller may only optionally narrow expected store coverage, never widen or fabricate it ([inventory-service.ts:65-71](../../../packages/core/src/operations/inventory-service.ts)).
