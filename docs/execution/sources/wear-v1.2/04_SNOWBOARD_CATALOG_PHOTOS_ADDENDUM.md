# スキー＋スノーボード：カタログ・写真の追加確定
Version1.2 / v1.1の写真分担と対象範囲だけを上書き

## 今回の変更
ユーザーの写真提供はスキーに加えて**スノーボードも含む**。v1.1にある「ボード写真は未手配」の断定を取り下げる。ブーツ・ウェアの写真も提供されるとは追加解釈しない。
サロモンは蔵王2拠点向けの入荷数量・モデル名。ChatGPTはスキーとスノーボードの対象季の製品リスト・詳細情報を収集。Codexはデータ取込/照合・個体生成計画・写真binding・説明・予約契約を接続する。メーカーにSKU/写真/長さの提供を一律必須にしないが不足は未確認扱い。
過去2季は2024/25・2025/26を作業前提、新季2026/27は別枠。ユーザーが別の対象年を指定したら置き換える。現物や履歴の参照がある旧版は削除しない。

## ボードの固有項目
正式モデル名、メーカーコード、製品版/掲載季、長さ、幅/waist、形状、profile、flex、用途、各数値の単位/出典、サイズ依存値、ブーツ・bindingの対応情報を**資料にある範囲だけ**保持する。数値仕様は長さ別、同名の別季やwide版を統合しない。画像だけで年式や商品コードを確定しない。
ボードには板/boots/bindings/youth/softgoodsの専用公式資料を使い、スキー用カタログの安全設定やブーツ規格を転用しない。公式入口[C01]を年式別に確認したが、全SKUの抽出と検証は未完了。
Premiumはモデル版＋長さ＋約束した仕様を各経路へ固定する。短め/長めで別モデルを混ぜない。Regularは従来モデル非確約。ブーツは左右1組同一ID、ボード本体は1枚1Asset。bindingまで今回新たな独立個体管理を強制せず、現在の台帳/受渡し構成に合わせて必要な適合情報を保持する。

## 写真一括取込
同じモデル版/グラフィックは代表写真を共有。全体表、必要なら裏、モデル/サイズ/コードラベルの確認用写真を一括で受ける。実際の長さは刻印等を確認。代表写真から同一納品の全個体長を推測しない。
モデルマスター作成後にstable model/variant codeを出力し、写真manifestで対応。似たファイル名や画像AI分類は候補に留める。filename+checksum+対象revisionを固定してdry-run→一括反映。未知/曖昧だけ確認キュー。
公開用の綺麗な写真と、識別ラベルの内部写真をrole/visibilityで分離。シリアルや内部棚情報を公開説明へ露出させない。ネット写真やAI生成物で未撮影の現物を装わない。
画像未着でも本文/版/在庫候補の下書きは続ける。写真未確認だけを当該画像の公開ゲートにする。画像と説明の版を公開releaseでそろえ、後の更新で過去予約の約束を変更しない。
